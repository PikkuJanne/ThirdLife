## Accessibility defect and runner record

The stage-transition focus issue was fixed and the original keyboard
cases passed on their recorded source. The backup review now clears
obsolete consent and scope when inputs or job context change.
[Stage focus regression](../evidence/TL-0608/stage-focus.md)

The external wheel runner first expired on the empty Jobs surface.
The next method waited for real vertical overflow in populated Intake.
A separate attempt routed the UI Automation bounds, pointer and window
hit test through physical screen coordinates. That run still observed
no scroll progress after the first detent. The pointer was restored and
the owned fixture exited normally. The result identifies the external
wheel observation as open. A later attempt needs a changed input route
or qualified observation of wheel delivery to the owned scroll surface.
[Microsoft UI Automation coordinate guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-screenscaling)

The existing full external command continues to include wheel checks.
The independently selectable `-VerifyAccessibility -KeyboardOnly`
mode completed in 8.828 s. Its result explicitly records that wheel
input was outside that run. The keyboard evidence therefore remains
available while the affected external wheel observation stays open.
Candidate scope and outstanding pilot accessibility claims remain
linked to the release decision.
