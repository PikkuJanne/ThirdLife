# TL-0116 — Audit accessibility defect evidence

**Environment.** 24 November 2026, `REF-CODEX-001` revision `2026-08-29.1`, Windows 11 x64 build 26300, unelevated interactive session, .NET SDK 10.0.400. The probes used only the isolated audit fixture. Windows accessibility, display, audio and input settings were left as found. No audio or personal content was captured.

| Reported defect | Technical finding | Disposition and limit |
| --- | --- | --- |
| Touchpad scrolling was uncontrollably fast in the first operator attempt. | The first application treated each spaced fractional wheel message as a full wheel step. Six −20 pulses moved the loaded WPF viewport 288 DIPs while one −120 detent moved it 48 DIPs. Commit `edb9b03ba813f5de67238d84dd424ad6da572257` applied proportional pixel scrolling, bounded pulse size and preserved queued offsets through layout. On the exact corrected launcher, Win32 `SendInput` moved the shell 2.22990% of its extent for a −120 detent and six individually spaced −20 messages each advanced it 0.37165 percentage points, ending at the same 2.22990%. A focused loaded-WPF test exposed a remaining 48-DIP jump for one −20 pulse over the unfocused, closed intake choice. The final correction applies proportional scrolling there and retains native selection when that control has keyboard focus or an open dropdown. | The demonstrated application acceleration defect is corrected on the tested Windows wheel input paths. The rate from the physical touchpad and the usability of a two-finger gesture remain unobserved on the corrected build. |
| The operator reported Narrator was unavailable or did not produce usable speech. | The first attempt recorded a running Narrator process and no usable speech. The preparation of the second fixture recorded text from its initial window in Speech Recap. An independent external UI Automation listener received `LiveRegionChanged` events in the exact corrected fixture for job creation, missing confirmation, the assessed gate becoming available, assessment running, assessment needing review, and report saved. The later read-only diagnostic found the Windows audio services running and the current default console render endpoint present, unmuted and above zero, with Narrator inactive in the session. | The reported no-speech failure remains on record. The earlier audible failure's cause remains undetermined. The tested product exposes these announcements to external assistive-technology clients. Neither current endpoint state, Narrator's process nor Speech Recap establishes earlier audio routing, sound or clarity. No app-side event delivery defect was found in these cases. |

The historical native-input and external-event probe took 4,610 ms before normal fixture close. It used the `edb9b03` Release launcher and UI assembly with SHA-256 `240f6220ecc12e11f5a9c5c7d6beb97b2e67103ddb0bab8395b1b41f11a2f2bb` and `f6028e00339048dd7c879679bee2bc5d1c12fdf842cd5b1f336da1fbaa25d77d`. The first probe timed out on an incorrect “Collection finished” expectation. The corrected assertion expects “Assessment needs review” because the fixture deliberately contains a failed provider. The [archived attempts](human-check.md) retain the actual observations and their original scope.

The focused `WheelOverAnUnfocusedIntakeChoiceScrollsTheShellProportionally` regression failed before the correction (48 DIPs against a maximum of 8.5, 859 ms) and passed after it (982 ms). The combined wheel, audit and shell accessibility filter passed 18 tests in 6 s with no failures or skips. It retains keyboard focus, nested evidence and report scrolling, proportional input and boundary coverage.

Run the maintained native check after building Release on the interactive active machine.
